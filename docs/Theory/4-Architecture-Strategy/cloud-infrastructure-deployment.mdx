# Cloud Infrastructure & Deployment

:::tip

**Persona Lens: Workshop & Interview Mode**
* **Quick Pitch:** Cloud infrastructure and deployment architecture provide the scalable, globally distributed physical and virtual substrate required to run resilient applications without managing bare-metal hardware.
* **Core Primitives:** Hyperscale regions, availability zone isolation, cloud compute models (IaaS/PaaS/Serverless), and container runtimes.
* **BAU & Operational Realities:** AZ outages, control-plane saturation, container resource starvation (OOM kills), and regional network latency spikes under load.
:::

## 🔍 Theory Focus Point

* **Global Infrastructure:** Focus on **availability zone isolation** and **multi-region redundancy** to evaluate fault blast radius and disaster recovery readiness.
* **Compute & Service Models:** Focus on **serverless execution limits** versus **container orchestration controls** to evaluate scalability and operational overhead.
* **Deployment & Delivery:** Focus on **immutable artifact packaging** and **progressive rollout patterns** to evaluate release safety and rollback velocity.

### ☁️ Global Cloud Infrastructure & Regions

:::tip

**Definition**
The globally distributed physical data centers, availability zones, and backbone networks that supply elastic compute, storage, and networking capacity on demand.
:::

> **Interview Pitch:** *"Cloud infrastructure abstracts physical data centers into globally accessible regions and isolated availability zones, giving you fault-tolerant scale without ever touching a server rack."*

#### 🧠 Decision Drivers
* **Choose / Prioritize Multi-Region Architecture:** High-availability systems requiring strict business continuity, disaster recovery, and low-latency global user access.
* **Choose / Prioritize Single-Region Deployment:** Internal tooling, early-stage MVPs, or systems bound by strict single-jurisdiction data residency laws.

#### 🧬 Core Primitives & Off-the-Cuff Explanations

| Primitive / Mechanism | Off-the-Cuff Explanation | Architectural Impact / Mechanism | Deep-Dive Research Term |
| :--- | :--- | :--- | :--- |
| **Availability Zone (AZ)** | Physically isolated data centers with independent power and cooling within a region. | Prevents local facility failures from taking down an entire regional architecture. | Fault-Isolated Zones |
| **Global Backbone Network** | Private fiber-optic infrastructure connecting cloud regions globally. | Bypasses the public internet for cross-region traffic, ensuring high throughput and security. | Private Cloud Backbone |
| **Edge Point of Presence (POP)** | Local caching and routing nodes positioned close to end users. | Accelerates content delivery and terminates SSL handshakes at the network edge. | Content Delivery Edge |

#### 🚨 Misapplication Diagnostics in Production

| Concept | Misapplication Scenario | Production BAU Symptom / Telemetry | Remediation |
| :--- | :--- | :--- | :--- |
| **Single-AZ Coupling** | Deploying all production compute and databases within a single availability zone. | Complete system outage when that specific data center facility suffers power or network failure. | Distribute application workloads across at least two or three availability zones per region. |

### ⚡ Compute & Architectural Models

:::tip

**Definition**
The abstraction layers (Virtual Machines, Containers, and Serverless Functions) that dictate how code is provisioned, executed, and scaled across cloud environments.
:::

> **Interview Pitch:** *"Compute models represent a sliding scale of control versus operational burden—from raw IaaS virtual machines giving you full OS access, to serverless functions that completely eliminate server management."*

#### 🧠 Decision Drivers
* **Choose / Prioritize Serverless / Managed Services:** Event-driven architectures, sporadic workloads, or teams seeking zero infrastructure maintenance overhead.
* **Choose / Prioritize Virtual Machines / Containers:** Long-running predictable workloads, legacy applications requiring OS-level access, or high-throughput real-time processing.

#### 🧬 Core Primitives & Off-the-Cuff Explanations

| Primitive / Mechanism | Off-the-Cuff Explanation | Architectural Impact / Mechanism | Deep-Dive Research Term |
| :--- | :--- | :--- | :--- |
| **Serverless Functions** | Event-driven code execution where the cloud provider handles all scaling and provisioning. | Eliminates idle infrastructure costs; introduces cold-start latency overhead. | Function-as-a-Service (FaaS) |
| **Containerization** | Packaging code and dependencies into isolated user-space instances sharing the host OS kernel. | Guarantees environment consistency across local development and production clusters. | OS-Level Virtualization |
| **Auto-Scaling Groups** | Automatically adding or removing compute instances based on real-time traffic metrics. | Absorbs traffic spikes dynamically while reducing costs during quiet hours. | Elastic Capacity Scaling |

#### 🚨 Misapplication Diagnostics in Production

| Concept | Misapplication Scenario | Production BAU Symptom / Telemetry | Remediation |
| :--- | :--- | :--- | :--- |
| **Cold-Start Latency** | Relying on serverless functions for synchronous APIs with strict sub-50ms latency SLAs. | Periodic unpredictable latency spikes when un-warmed function containers initialize. | Keep serverless instances warm or shift predictable low-latency APIs to persistent container runtimes. |

### 🚀 Containerization & Deployment Architecture

:::tip

**Definition**
The architectural discipline governing how immutable application artifacts are packaged, versioned, and rolled out safely across environments using progressive deployment patterns.
:::

> **Interview Pitch:** *"Containerization and deployment pipelines ensure that code moves smoothly from a developer's commit to production through automated, test-gated, and rollback-safe delivery paths."*

#### 🧠 Decision Drivers
* **Choose / Prioritize Progressive Delivery (Canary/Blue-Green):** Enterprise production systems where zero downtime and minimal blast radius during releases are mandatory.
* **Choose / Prioritize Direct Recreate Deployments:** Internal batch scripts or non-critical development environments where brief downtime is acceptable.

#### 🧬 Core Primitives & Off-the-Cuff Explanations

| Primitive / Mechanism | Off-the-Cuff Explanation | Architectural Impact / Mechanism | Deep-Dive Research Term |
| :--- | :--- | :--- | :--- |
| **Canary Release** | Routing a tiny percentage of live production traffic to a new version to test health. | Limits blast radius of bugs to a small fraction of users before full rollout. | Progressive Traffic Shifting |
| **Immutable Artifacts** | Versioned, read-only build packages (container images) that never change after compilation. | Eliminates configuration drift between staging and production environments. | Immutable Infrastructure |
| **Liveness & Readiness Probes** | Automated health checks managed by orchestrators to determine pod health and traffic routing. | Automatically restarts crashed containers and stops routing traffic to unready nodes. | Orchestrator Health Probing |

#### 🚨 Misapplication Diagnostics in Production

| Concept | Misapplication Scenario | Production BAU Symptom / Telemetry | Remediation |
| :--- | :--- | :--- | :--- |
| **Missing Resource Limits** | Deploying containers without defining strict CPU and memory resource requests/limits. | One runaway container consuming all node RAM, triggering kernel OOM-kills across neighboring pods. | Enforce strict CPU and memory requests and limits on all container deployment manifests. |
