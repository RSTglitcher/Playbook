# 📘 Regular Expressions & Pattern Matching

:::tip

## Regular Expressions & Pattern Matching

**What is it?**
A structured technical skill used to define precise pattern syntax to search, match, extract, validate, and manipulate text strings across command-line tools, programming languages, and data observability pipelines.

#### 📚 Related Theory & Practice References
* Theory — Formal language theory, finite automata, and string parsing principles.
* Practice — CLI grep operations, log parsing queries, and code refactoring search patterns.
:::

## 🧭 When is it Used?

| When to Use | When Not to Use |
| :--- | :--- |
| • Validating structured string inputs (e.g., email addresses, postal codes, IP addresses) in applications. • Extracting logs, identifying error codes, or filtering unstructured telemetry streams. • Performing complex find-and-replace transformations during code refactoring or data cleanup. | • Parsing fully nested or context-free languages like arbitrary HTML or XML trees (where dedicated parsers should be used instead). • Simple exact-string searches where standard string inclusion methods (`indexOf`, `contains`) suffice. |

---

## 💡 What Value Does It Bring?

* **Accelerates Text Processing:** Replaces complex, multi-line conditional string loops with concise, declarative pattern expressions.
* **Enforces Strict Validation:** Guarantees that user inputs and system payloads conform to exact structural contracts before processing.
* **Simplifies Log Analysis:** Unlocks powerful filtering and extraction capabilities across massive observability and monitoring datasets.

---

## 🧠 Core Concepts

| Concept / Mechanism | Plain English Explanation | Execution Impact |
| :--- | :--- | :--- |
| **Anchors & Boundaries** | Special markers (`^`, `$`, `\b`) that specify the exact start, end, or word boundary of a target string match. | Prevents partial or unintended substring matches by locking pattern evaluation to specific boundaries. |
| **Character Classes & Shorthands** | Condensed groupings (`\d` for digits, `\w` for word characters, `[a-z]` for ranges) representing sets of acceptable characters. | Keeps regex patterns compact, readable, and adaptable to varied character sets. |
| **Quantifiers & Greediness** | Modifiers (`*`, `+`, `{n,m}`) that dictate how many times a preceding character or group must repeat. | Controls whether pattern matching consumes as much text as possible (greedy) or stops early (lazy). |

---

## 📋 Common Patterns

1. **Phase 1: Pattern Objective & Boundary Definition** — Establish whether the pattern is used for validation, search filtering, or extraction, and set strict start/end anchors.
2. **Phase 2: Core Pattern Assembly** — Combine character classes, quantifiers, and capturing groups to isolate the target string format.
3. **Phase 3: Testing & Execution** — Evaluate the regex against positive and negative test strings using runtime functions or CLI tools (`grep`, `sed`).

## 🛠️ Practical Tips & Templates

> **Template / Artifact Example:** Regex Fundamentals and Pattern Matching Patterns.

```regex
# 1. Basic Character Fundamentals & Anchors
^               -> Start of line anchor
$               -> End of line anchor
\d              -> Any single digit (0-9)
\w              -> Any word character (a-z, A-Z, 0-9, _)
\s              -> Any whitespace character

# 2. Quantifiers & Repetition
{3}             -> Exactly 3 occurrences
+               -> One or more occurrences
*               -> Zero or more occurrences
?               -> Zero or one occurrence

# 3. Basic String Matching (Hello World / Email validation)
^\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b$

# 4. Common Application Functions (JavaScript Example)
const regex = /^\d{3}-\d{2}-\d{4}$/;
const isValidSSN = regex.test("123-45-6789");

const text = "Contact support@example.com for help.";
const emailMatch = text.match(/\b[\w.-]+@[\w.-]+\.\w+\b/);

```

:::warning

### Pitfalls & Edge Cases

* **Common Mistake:** Writing overly complex, unreadable "write-only" regex strings that lack comments or breakdown, making maintenance nearly impossible.
* **Pro Tip:** When matching complex strings like HTML or deeply nested data, prefer dedicated parsers over regex to avoid brittle failure modes on edge-case inputs.
:::
