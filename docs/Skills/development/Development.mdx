:::tip

**Domain Philosophy:** Writing code—whether in SQL, Python, Java, or LLM Prompts—is not just about getting a script to run. True development capability is about **engineering quality**: writing maintainable, well-tested, self-documenting code that operates safely in production environments.

:::

---

## 1. What It Means to Focus on Engineering Quality

While **Analysis** frames the problem, **Business** evaluates impact, and **Delivery** ensures predictable flow, **Development** is about technical craftsmanship and execution standards.

Regardless of the stack or language, high-quality engineering follows five universal principles:

1. **Readability & Intent:** Code is read far more often than it is written. Variable names, schemas, and prompts must be explicit and self-documenting.
2. **Defensive Design & Error Handling:** Anticipating bad inputs, missing parameters, system timeouts, and edge cases gracefully.
3. **Testability & Determinism:** Writing modular code, pure functions, and structured SQL/prompts that produce predictable, reproducible outcomes.
4. **Maintainability & DRY (Don't Repeat Yourself):** Abstracting common logic into reusable modules, libraries, or SQL models (e.g., dbt macros).
5. **Operational Safety:** Ensuring secrets are decoupled, database migrations are non-breaking, and code passes automated CI/CD quality gates.

## 2. Quality Standards Across Language Stacks

| Language / Domain | Focus Area | Quality Standard |
| :--- | :--- | :--- |
| **SQL & Data Transformations** | Schema Modeling & Logic | Deterministic joins, explicit CTEs over nested subqueries, idempotency, and automated dbt tests. |
| **Python** | Scripting, APIs & Data Pipelines | Type hinting (`mypy`), strict PEP 8 formatting (`ruff`/`black`), explicit exception handling, and unit test coverage (`pytest`). |
| **Java** | Object-Oriented & Microservices | Clean architecture, strict OOP encapsulation, immutable state models, and comprehensive JUnit/integration testing. |
| **Prompt Engineering** | LLM System Prompts | Zero-shot/few-shot framing, structured output schemas (JSON/Pydantic), deterministic guardrails, and context bounds. |

## 4. Engineering Quality Checklist

Before submitting a Pull Request or pushing code to staging, verify:

- [ ] Does the code pass automated linting and formatting checks?
- [ ] Are functions/methods typed and bounded with explicit inputs and return types?
- [ ] Is exception handling specific (avoiding bare `except:` or generic `catch (Exception e)`)?
- [ ] Are unit tests written to cover both happy paths and boundary/failure cases?
- [ ] Are credentials, API keys, and environment-specific configs completely decoupled from source control?
