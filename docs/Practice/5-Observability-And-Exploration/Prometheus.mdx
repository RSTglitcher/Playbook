# 📘 Prometheus Monitoring & Alerting

:::tip

## Prometheus Monitoring & Alerting

**What is it?** 
Prometheus is an open-source systems monitoring and alerting toolkit built around a dimensional time-series database. It collects and stores metrics as time series data, leveraging a powerful query language (PromQL) and flexible service discovery mechanisms.

### 📚 Related Theory References
* Observability & Exploration — Architecture of metric collection, pull-based scraping models, and time-series data storage contracts.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • Pull-based metric collection and dimensional time-series data monitoring.<br>• Cloud-native containerized workloads (Kubernetes) and microservice performance tracking.<br>• High-frequency alerting and automated threshold evaluations via PromQL. | • Long-term raw event log storage or full-text string searching (use Loki or Elasticsearch instead).<br>• Distributed transaction tracing across complex request chains (use Jaeger or Datadog APM).<br>• Massive multi-tenant global metrics aggregation without a federated or long-term remote write backend. |

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with Prometheus?
1. **Local Environment:** Client utilities installed locally (`curl`, `promtool`) or direct web browser access to the Prometheus dashboard.
2. **Configuration Setup:** Scrape configuration targets defined in `prometheus.yml`, appropriate IAM roles or network security groups for target scraping, and alert rule definitions.

---

## 🔑 Tool Requirements

* **Access URL / Portal:** Prometheus server endpoint URL or operational web UI (e.g., `http://prometheus.internal.enterprise.com:9090`).
* **Authentication Method:** Reverse proxy Basic Authentication, OAuth 2.0 sidecar tokens, or mutual TLS (mTLS) certificates.
* **Initial Setup Check:** Verify server health, target scrape statuses, and rule evaluations using standard health probes (`/-/ready` or `/-/healthy`) before querying metrics.

## 📋 Common & Useful Workflows

```bash
# 1. Check Prometheus server health and readiness endpoints
curl -s [http://prometheus.internal.enterprise.com:9090/-/ready](http://prometheus.internal.enterprise.com:9090/-/ready)

# 2. Query active targets and scrape health via the API
curl -s [http://prometheus.internal.enterprise.com:9090/api/v1/targets](http://prometheus.internal.enterprise.com:9090/api/v1/targets) | jq '.data.activeTargets[] | {scrapeUrl: .scrapeUrl, health: .health}'

# 3. Execute a PromQL query via the HTTP API to calculate request rate over 5 minutes
curl -G "[http://prometheus.internal.enterprise.com:9090/api/v1/query](http://prometheus.internal.enterprise.com:9090/api/v1/query)" \
  --data-urlencode "query=rate(http_requests_total[5m])" | jq '.'

# 4. Validate local Prometheus configuration syntax using promtool
promtool check config prometheus.yml

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common Prometheus platform and telemetry failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **Targets Down / Scrape Failures** | Network partition, target application crash, or misconfigured scrape URL/port. | Target status page (`/targets`), security groups, and target application health logs. | Fix network path or firewall rules, restart target service, or correct scrape endpoint configuration. |
| **High Memory / OOM Killer** | Cardinality explosion from high-label variations or excessively long retention windows. | TSDB status metrics, active series counts, and memory consumption graphs. | Restrict label cardinality, drop unused metrics via relabeling rules, or adjust container memory limits. |
| **Alerts Not Firing** | Incorrect PromQL evaluation logic, rule syntax error, or alerting engine crash. | Prometheus alert rules page (`/rules`), server logs, and expression query test outputs. | Fix expression syntax in alert rules, reload Prometheus configuration (`/-/reload`), and test queries. |
| **Slow PromQL Queries** | Overly broad range selectors, high-cardinality group aggregates, or disk I/O bottlenecks. | Query runtime metrics, expression execution duration, and underlying storage disk IOPS. | Optimize PromQL queries by adding granular matchers, reducing time windows, or tuning storage specs. |
