# 📘 Elasticsearch Distributed Search Engine

:::tip

## Elasticsearch Distributed Search Engine

**What is it?** 
Elasticsearch is a distributed, RESTful search and analytics engine built on Apache Lucene. It enables full-text search, structured log analytics, time-series analysis, and real-time querying across massive distributed datasets.

### 📚 Related Theory References
* Observability & Exploration — Architecture of inverted indices, distributed sharding, and real-time text analysis.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • Full-text search, fuzzy matching, and real-time relevance scoring across large corpuses. • Centralized log analytics, observability search, and time-series aggregations. • Distributed search workloads requiring horizontal scaling and fault tolerance. | • Strict relational transaction (OLTP) workloads requiring ACID compliance. • Simple small datasets where standard relational database queries suffice. • Long-term cold storage archiving where high-performance indexing is unnecessary. |

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with Elasticsearch?
1. **Local Environment:** Client utilities installed locally (`curl`, `jq`, or Kibana console access).
2. **Configuration Setup:** Cluster transport endpoints, API keys or Basic Authentication credentials, and explicit index mapping templates.

---

## 🔑 Tool Requirements

* **Access URL / Portal:** Elasticsearch cluster endpoint URL (e.g., `https://es-cluster.internal.enterprise.com:9200`) or Kibana UI portal.
* **Authentication Method:** API Keys (`Authorization: ApiKey <key>`) or Basic Authentication credentials (`user:password`).
* **Initial Setup Check:** Verify cluster health and node availability using command-line probes (`/_cluster/health`) before writing or querying indices.

## 📋 Common & Useful Workflows

```bash
# 1. Check cluster health and node status
curl -u user:password [https://es-cluster.internal.enterprise.com:9200/_cluster/health?pretty](https://es-cluster.internal.enterprise.com:9200/_cluster/health?pretty)

# 2. Create an index with explicit field mappings and token analyzers
curl -X PUT [https://es-cluster.internal.enterprise.com:9200/my_index](https://es-cluster.internal.enterprise.com:9200/my_index) \
  -H 'Content-Type: application/json' \
  -d '{
    "mappings": {
      "properties": {
        "message": { "type": "text" },
        "timestamp": { "type": "date" }
      }
    }
  }'

# 3. Index a structured JSON document
curl -X POST [https://es-cluster.internal.enterprise.com:9200/my_index/_doc](https://es-cluster.internal.enterprise.com:9200/my_index/_doc) \
  -H 'Content-Type: application/json' \
  -d '{"message": "system error encountered", "timestamp": "2026-06-06T00:00:00Z"}'

# 4. Search documents using Query DSL
curl -X GET [https://es-cluster.internal.enterprise.com:9200/my_index/_search](https://es-cluster.internal.enterprise.com:9200/my_index/_search) \
  -H 'Content-Type: application/json' \
  -d '{"query": {"match": {"message": "error"}}}'

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common Elasticsearch platform failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **Cluster Red Status** | Missing primary shards resulting from node crashes or split-brain isolation. | `/_cluster/health`, `/_cat/shards`, and node system logs. | Restore missing primary shards, fix node network partitions, or restart failed nodes. |
| **Cluster Yellow Status** | Missing replica shards due to unassigned placement rules or cluster capacity. | Replica count settings, node availability, and disk watermark thresholds. | Add cluster nodes or adjust shard allocation rules to let replicas settle. |
| **High JVM Heap Usage** | JVM memory pressure from large queries, heavy aggregations, or unbounded field mapping. | Node stats, Garbage Collection logs, and query complexity profiles. | Optimize resource-heavy queries, reindex bloated fields, or scale up heap limits. |
| **Indexing Failures (429/503)** | Mapping type conflicts, unhandled schema changes, or full disk watermarks. | `/_cat/indices`, disk free space metrics, and server error logs. | Fix mapping violations, free storage space, or trigger disk watermark adjustments. |
