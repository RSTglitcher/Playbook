# 📘 Amazon Web Services (AWS)

:::tip

## Amazon Web Services (AWS)

**What is it?** 
AWS provides a broad suite of cloud services including compute, storage, database, messaging, and analytics. This runbook focuses on key data and messaging services commonly used by engineers: *ElastiCache, DynamoDB, Keyspaces, SQS, and SNS*.

### 📚 Related Theory References
* Distributed Systems — Core architecture and replication models.
* Data Engineering — Partitioning and distributed data guarantees.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • You need managed, scalable cloud services. | • You require full control over hardware or OS. |
| • You need serverless or autoscaling data systems. | • You need strict on-premises or air-gapped environments. |
| • You want managed messaging (SQS/SNS) or low-ops NoSQL storage (DynamoDB/Keyspaces). | • You need complex relational joins or OLAP workloads. |

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with AWS services?
1. **Local Environment:** AWS CLI installed locally, along with service-specific clients (`redis-cli`, `cqlsh`).
2. **Configuration Setup:** Authenticated AWS profile (`aws configure`) with valid Access Keys, Secret Keys, and target Region.

---

## 🔑 Tool Requirements

* **Access URL / Portal:** [AWS Management Console](https://aws.amazon.com/console/)
* **Authentication Method:** Single Sign-On (SSO) or MFA-secured IAM roles mapped with least-privilege permissions.
* **Initial Setup Check:** Verify active identity (`aws sts get-caller-identity`) and ensure VPC endpoints, subnets, and security groups are correctly provisioned for target services.

---

## 📋 Common & Useful Workflows

```bash
# 1. Authenticate and verify active session identity
aws sts get-caller-identity

# 2. Inspect DynamoDB table structure and throughput metrics
aws dynamodb describe-table --table-name <table-name>

# 3. Connect to ElastiCache Redis cluster
redis-cli -h <primary-endpoint> -p <port>

# 4. Check SQS queue depth and attributes
aws sqs get-queue-attributes --queue-url <queue-url> --attribute-names All

# 5. Publish a message to an SNS topic
aws sns publish --topic-arn <topic-arn> --message "Alert message payload"

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common AWS platform failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **ElastiCache Cluster Down** | Node crash, network isolation, or scaling limit. | Cluster status, node events, VPC security group connectivity. | Restart node/cluster or verify subnet and port permissions. |
| **DynamoDB Table Unavailable** | Provisioned throughput exceeded or table deleted. | Table status flags and CloudWatch RCU/WCU metrics. | Scale table capacity or recreate table if dropped. |
| **Keyspaces Not Reachable** | VPC endpoint or Cassandra SSL misconfiguration. | Keyspace describe status and SSL certificate trust store. | Fix network routing/security groups and verify CQLSH SSL parameters. |
| **SQS Messages Delayed / Lost** | Consumer failure or visibility timeout mismatch. | Queue attributes, DLQ depth, and CloudWatch message age. | Restart consumer workers and check IAM send/receive permissions. |
| **SNS Notifications Failed** | Subscription filter policy block or IAM throttling. | Topic subscription list and CloudWatch delivery failure logs. | Adjust IAM policies and correct subscription endpoints. |
| **IAM Access Denied** | Insufficient permissions on user or execution role. | IAM policies, attached inline roles, and resource policies. | Grant required least-privilege role permissions. |
| **API Quota Exceeded / 429** | Request rate exceeds default service limits. | Service quotas dashboard and CloudWatch request logs. | Request quota increase or implement exponential backoff. |
