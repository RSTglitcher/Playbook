# 📘 Apache Kafka

:::tip

## Apache Kafka

**What is it?** 
Apache Kafka is a distributed event streaming platform used to ingest, store, and process high-volume real-time data using an append-only log. It enables scalable, fault-tolerant, real-time pipelines and event-driven architectures.

### 📚 Related Theory References
* Distributed Systems — Core architecture, append-only logs, and cluster consensus models.
* Data Engineering — Partitioning, distributed data guarantees, and event streaming patterns.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • Real-time streaming between microservices and disparate systems. | • Request/response synchronous workflows (use REST/gRPC instead). |
| • High-throughput ingestion (Megabytes to Gigabytes per second). | • Complex routing or inline transformations (use Kafka Connect or ESB). |
| • Event-driven architecture and asynchronous messaging. | • Long-term analytics storage or data warehousing. |
| • Durable log systems requiring stream replay capabilities. | • Low-volume workloads where simpler message queues suffice. |
| • Decoupling producers from concurrent consumers. | • Systems requiring strict global multi-partition ordering. |

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with Kafka?
1. **Local Environment:** Apache Kafka client binaries installed locally (including `kafka-topics.sh`, `kafka-console-producer.sh`, `kafka-consumer-groups.sh`).
2. **Configuration Setup:** Client properties configuration for security, including TLS truststores/keystores or SASL credential profiles.

---

## 🔑 Tool Requirements

* **Access URL / Portal:** Dedicated internal broker endpoints or Confluent UI portals.
* **Authentication Method:** TLS/mTLS client certificates or SASL credentials alongside topic-level Access Control Lists (ACLs) and Schema Registry access.
* **Initial Setup Check:** Verify cluster broker reachability (`nc -z <broker> 9092`), validate bootstrap server stability, and confirm topic metadata descriptions.

## 📋 Common & Useful Workflows

```bash
# 1. List all available Kafka topics on the target cluster
kafka-topics.sh --bootstrap-server <broker>:9092 --list

# 2. Describe topic partitions, leaders, and replication configuration
kafka-topics.sh --describe --topic <topic-name> --bootstrap-server <broker>:9092

# 3. Create a new topic with custom partitions and replication factor
kafka-topics.sh --create --topic <topic-name> --bootstrap-server <broker>:9092 --partitions 3 --replication-factor 2

# 4. Inspect consumer group lag and offsets
kafka-consumer-groups.sh --bootstrap-server <broker>:9092 --describe --group <group-name>

# 5. Consume messages from the beginning of a topic for validation
kafka-console-consumer.sh --bootstrap-server <broker>:9092 --topic <topic-name> --from-beginning

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common platform failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **Brokers Down** | Node failure, JVM crash, or network partition. | Broker logs, cluster controller status, and node health. | Restart the broker service, resolve network blocks, or rebalance partitions. |
| **Consumer Lag Spikes** | Slow consumers, thread starvation, or blocked processing. | Consumer offsets, lag metrics, and partition skew. | Add worker consumers, optimize processing code, or rebalance group partitions. |
| **Topic Unavailable** | Missing topic, ACL restrictions, or broker configuration error. | Active topic lists, broker ACL bindings, and server logs. | Recreate the topic if deleted or correct user ACL permissions. |
| **Messages Not Delivered** | Retention limits exceeded or partition offline. | Topic retention policies and partition leadership status. | Increase data retention duration or restore offline partition replicas. |
| **Hot Partitions** | Poor partition key distribution causing uneven traffic. | Partition-level message count metrics and key strategies. | Redesign the partition key distribution logic or increase partition count. |
| **High Disk Usage** | Retention configured too long or log compaction failure. | Topic storage size and active segment file counts. | Adjust time/size-based retention policies or trigger log compaction. |
| **Serialization Errors** | Schema mismatch between producers and consumers. | Producer/consumer client logs and Schema Registry versions. | Fix schema definitions and enforce schema registry validation rules. |
| **Authentication Failed / 401** | Expired certificates or incorrect SASL credentials. | Keystores, truststore file paths, and client config files. | Refresh SSL certificates or update authentication credentials. |
