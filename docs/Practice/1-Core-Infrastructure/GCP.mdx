# 📘 Google Cloud Platform (GCP)

:::tip

## Google Cloud Platform (GCP)

**What is it?** 
GCP is a cloud platform providing compute, storage, analytics, and messaging services. This runbook focuses on key data and messaging services used by engineers: *BigQuery, BigTable, Cloud Storage, and Pub/Sub*.

### 📚 Related Theory References
* Distributed Systems — Core architecture and cluster consensus models.
* Data Engineering — Partitioning and distributed data guarantees.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • Large-scale analytics using BigQuery. | • OLTP workloads requiring strict row-level transactions. |
| • High-throughput event ingestion via Pub/Sub. | • Complex routing or guaranteed strict queue ordering. |
| • Wide-column NoSQL workloads using BigTable. | • Small datasets or relational multi-table joins. |
| • Durable object storage for logs, files, and ML artifacts. | • Low-latency block storage requirements. |
| • Serverless, autoscaling distributed data pipelines. | • Real-time in-memory stream compute workloads. |

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with GCP services?
1. **Local Environment:** Google Cloud SDK (`gcloud`, `bq`, `cbt`, `gsutil`) installed locally.
2. **Configuration Setup:** Authenticated active user profile and project configuration.

---

## 🔑 Tool Requirements

* **Access URL / Portal:** [GCP Console](https://console.cloud.google.com/)
* **Authentication Method:** Service account keys or user-authenticated IAM sessions with least-privilege roles.
* **Initial Setup Check:** Verify active identity (`gcloud auth list`), correct active project (`gcloud config get-value project`), and ensure required service APIs are enabled per project.

## 📋 Common & Useful Workflows

```bash
# 1. Authenticate with GCP and set target project
gcloud auth login
gcloud config set project <PROJECT_ID>

# 2. Inspect a BigQuery table schema
bq show --schema --format=prettyjson <project>:<dataset>.<table>

# 3. Run a BigQuery analysis query
bq query --use_legacy_sql=false 'SELECT COUNT(*) FROM dataset.table'

# 4. Explore a Cloud Storage bucket
gsutil ls gs://bucket-name/

# 5. Inspect a Pub/Sub subscription backlog
gcloud pubsub subscriptions describe <subscription-name>

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common GCP platform failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **BigQuery Query Fails** | Invalid SQL syntax or missing permissions. | Query syntax errors and dataset IAM roles. | Fix query syntax or grant required roles. |
| **Pub/Sub Message Loss** | Misconfigured subscription delivery or consumer down. | Subscription configuration and consumer logs. | Fix subscription settings or restart consumer workers. |
| **BigTable Slow Reads** | Data hotspotting or insufficient active cluster nodes. | Row key design patterns and cluster CPU usage metrics. | Redesign row keys to distribute load or scale cluster nodes. |
| **IAM Access Denied** | Missing roles or invalid policy bindings. | IAM policy bindings on project/dataset level. | Grant required IAM roles to user or service account. |
| **API Quota Exceeded / 429** | Request rate exceeds default project limits. | Cloud Monitoring quotas and API logs. | Request quota limits increase or implement rate limiting/backoff. |
| **Cloud Storage Access Denied** | Bucket-level policy block or missing object permissions. | IAM bindings and uniform bucket-level access settings. | Fix IAM permissions or update bucket security policies. |
