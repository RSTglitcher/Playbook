# 📘 Databricks Unified Analytics Platform

:::tip

## Databricks Unified Analytics Platform

**What is it?** 
Databricks is a unified analytics and data engineering platform built on top of Apache Spark. It provides collaborative notebooks, scalable compute clusters, Delta Lake storage, and orchestration for ETL, ML, and analytics workloads.

### 📚 Related Theory References
* Data Engineering & Storage — Architecture of distributed spark compute engines, Lakehouse storage patterns, and ACID delta tables.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • Large-scale distributed ETL/ELT data processing pipelines.  • Collaborative data science notebooks and machine learning feature engineering.  • Delta Lake architecture requiring ACID guarantees on top of cloud object storage. | • Small datasets easily handled by a standard relational warehouse.  • Real-time low-latency microservice APIs.  • Simple SQL-only transformations (use dbt instead). |

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with Databricks?
1. **Local Environment:** Databricks CLI installed locally (`pip install databricks-cli`).
2. **Configuration Setup:** Databricks host URL, personal access token configured via `databricks configure --token`, and appropriate Unity Catalog scopes.

---

## 🔑 Tool Requirements

* **Access URL / Portal:** Databricks workspace tenant enterprise URL (e.g., `https://adb-xxxx.azuredatabricks.net` or AWS/GCP workspace equivalent).
* **Authentication Method:** OAuth, Personal Access Tokens (PAT), or cloud IAM integration.
* **Initial Setup Check:** Verify workspace reachability and active cluster availability using the Databricks CLI or web UI before submitting jobs.

## 📋 Common & Useful Workflows

```bash
# 1. Configure Databricks CLI credentials and validate authentication
databricks configure --token
databricks workspace ls

# 2. List active compute clusters and jobs
databricks clusters list
databricks jobs list

# 3. Submit a job or run a notebook programmatically
databricks jobs run-now --job-id <job_id>

# 4. Inspect Delta table metadata and transaction history via Spark SQL
spark.sql("DESCRIBE DETAIL my_delta_table").show()
spark.sql("DESCRIBE HISTORY my_delta_table").show()

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common Databricks platform failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **Job Failing** | Notebook code exception, cluster misconfiguration, or missing library dependency. | Job run logs, cluster configuration settings, and exception stack traces. | Fix code bugs, adjust cluster node/runtime definitions, or install required cluster libraries. |
| **Slow Job Performance** | Underpowered cluster, data skew, or inefficient shuffle partitions. | Cluster CPU/memory metrics and Spark UI execution stages. | Scale up cluster node sizes, repartition data keys, or tune Spark configuration properties. |
| **Delta Table Corruption** | Interrupted concurrent writes or schema mismatch conflicts. | Delta history logs (`DESCRIBE HISTORY`) and checkpoint metadata. | Roll back to a previous valid version using time-travel or fix schema definitions and reprocess. |
| **Cluster Not Starting** | Cloud provider instance type unavailability, network limit, or VPC subnet exhaustion. | Cluster event logs and cloud provider infrastructure capacity limits. | Switch to an alternate node type family or fix VPC subnet configurations. |
