# 📘 dbt Data Transformation Framework

:::tip

## dbt Data Transformation Framework

**What is it?** 
dbt (data build tool) is a data transformation framework that enables data analysts and analytics engineers to transform data in their warehouses more effectively by writing modular SQL models, enforcing automated data quality tests, managing dependencies, and generating documentation.

### 📚 Related Theory References
* Data Engineering & Storage — Architecture of analytical data models, DAG dependency scheduling, and modular transformation layers.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • SQL-based transformations inside cloud data warehouses (Snowflake, BigQuery, Databricks). • Enforcing data quality testing, lineage tracking, and version-controlled analytics code. • Managing structured multi-layer data models (staging, intermediate, marts). | • Heavy ETL/ELT pipelines requiring raw Python or Spark code execution. • Real-time low-latency streaming data transformations. • Non-SQL workloads or operational transactional database updates. |

---

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with dbt?
1. **Local Environment:** dbt core or CLI installed locally (`pip install dbt-core dbt-snowflake` or relevant adapter).
2. **Configuration Setup:** Project configuration in `dbt_project.yml` and local connection profiles defined in `~/.dbt/profiles.yml`.

---

## 🔑 Tool Requirements

* **Access URL / Portal:** Cloud data warehouse dashboard endpoint or dbt Cloud web portal.
* **Authentication Method:** Warehouse credentials, OAuth tokens, or SSH/key-pair integrations via `profiles.yml`.
* **Initial Setup Check:** Verify connection health and profile configurations using diagnostic commands (`dbt debug`) before executing models.

---

## 📋 Common & Useful Workflows

```bash
# 1. Verify local profile connectivity and project configuration
dbt debug

# 2. Compile SQL models without executing them against the warehouse
dbt compile

# 3. Execute all transformation models in the project DAG
dbt run

# 4. Run automated data quality tests across models
dbt test

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common dbt platform and execution failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **Model Compilation / Execution Failure** | Syntax error in SQL, missing table reference, or invalid `ref()` macro call. | `dbt run` terminal logs, warehouse error output, and target schema state. | Fix SQL syntax errors, update broken model references, and re-run transformation. |
| **Data Quality Test Failure** | Unmet constraints (`unique`, `not null`) or upstream source data corruption. | `dbt test` failure output and corresponding model source tables. | Correct source data anomalies or fix transformation logic, then re-run tests. |
| **Broken DAG Dependencies** | Misconfigured model parent/child references or deleted base nodes. | `dbt ls` graph output and project model folder structures. | Update node dependency mapping, verify schema files, and re-compile project. |
| **Slow Run Performance** | Large table scans without incremental strategies or unoptimized joins. | Warehouse query history and execution timing metrics per model. | Convert large models to incremental strategies, add partitioning, or optimize SQL code. |
