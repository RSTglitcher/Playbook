# 📘 Apache Cassandra Distributed NoSQL Database

:::tip

## Apache Cassandra Distributed NoSQL Database

**What is it?** 
Apache Cassandra is a distributed, wide-column NoSQL database designed for massive scalability, high availability, and zero single points of failure across commodity hardware or cloud infrastructure.

### 📚 Related Theory References
* Data Engineering & Storage — Architecture of peer-to-peer distribution, consistent hashing, and log-structured merge storage.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • High-write, high-availability workloads requiring linear horizontal scaling. • Multi-region or multi-datacenter active-active replication deployments. • Predictable low-latency operations with heavy append-only write patterns. | • Complex relational data modeling requiring strict ACID transactions or multi-table joins. • Small datasets where simpler single-node or relational databases suffice. • Heavy analytical (OLAP) querying without pre-aggregated data paths. |

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with Cassandra?
1. **Local Environment:** Cassandra client utilities installed locally (`cqlsh`, `nodetool`).
2. **Configuration Setup:** Cluster seed node IP list configured in `cassandra.yaml`, correct rack/datacenter attributes defined, and authentication credentials enabled.

---

## 🔑 Tool Requirements

* **Access URL / Portal:** Cluster node IP addresses via terminal shell or JMX port monitoring tools.
* **Authentication Method:** CQL username and password (`cqlsh -u <user> -p <password>`) or mutual TLS (mTLS) cluster communication.
* **Initial Setup Check:** Verify cluster operational status (`nodetool status`) and keyspace configurations before running operational writes or schema changes.

---

## 📋 Common & Useful Workflows

```bash
# 1. Check cluster node health, status, and data load distribution
nodetool status

# 2. Connect to the cluster via cqlsh
cqlsh <node_ip> -u <username> -p <password>

# 3. Create a multi-datacenter keyspace with NetworkTopologyStrategy
CREATE KEYSPACE my_keyspace WITH replication = {
  'class': 'NetworkTopologyStrategy',
  'dc1': 3
};

# 4. Inspect compaction backlogs and pending thread pool tasks
nodetool compactionstats
nodetool tpstats

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common Apache Cassandra platform failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **Node Down / Unreachable** | Hardware failure, network partition, or JVM OutOfMemory crash. | `nodetool status`, system logs (`/var/log/cassandra/system.log`), and host reachability. | Restart the node service, inspect JVM heap settings, or trigger a cluster rebalance/repair if unrecoverable. |
| **Cluster Inconsistency** | Missed node writes during network splits or unperformed background node repairs. | Repair execution history, hinted handoff queues, and replication settings. | Run incremental repairs (`nodetool repair`) and verify proper replication factor configurations. |
| **Slow Queries / Timeouts** | Unindexed filtering queries (`ALLOW FILTERING`), heavy partition hotspots, or row bloat. | Query logs, partition size distributions, and schema design clustering columns. | Optimize query patterns, add secondary indexes or Materialized Views, and refactor partition keys. |
| **High Disk Usage / SSTables** | Compaction backlog, uncollected tombstones, or missing maintenance routines. | `nodetool compactionstats`, disk partition metrics, and tombstone warnings in logs. | Trigger manual compaction (`nodetool compact`), clean old snapshots, or expand cluster storage. |
