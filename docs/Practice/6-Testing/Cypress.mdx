# 📘 Cypress E2E Testing

:::tip

## Cypress E2E Testing

**What is it?** 
Cypress is a modern, browser-native end-to-end testing framework that runs directly in the browser runtime. It provides a deterministic execution model, automatic waiting, and time-travel debugging for web application UIs.

### 📚 Related Theory References
* Test Automation — Core philosophy of UI test automation, selector stability, and the testing pyramid.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • Testing modern single-page applications (React, Vue, Angular). • Validating user journeys and end-to-end browser flows. • Intercepting network requests to test UI behavior under mock conditions. | • Multi-tab or multi-domain routing scenarios. • Heavy backend-only API testing or high-performance load testing. • Low-level micro-unit logic calculations. |

---

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with Cypress?
1. **Local Environment:** Node.js runtime and Cypress package installed locally (`npm install cypress --save-dev`).
2. **Configuration Setup:** Cypress configuration file (`cypress.config.js`) and test spec directory (`cypress/e2e/`).

---

## 🔑 Tool Requirements

* **Access URL / Portal:** Local interactive test runner GUI (`npx cypress open`) or headless CI terminal output.
* **Authentication Method:** Local environment variables or programmatic API login seeding before test specs execute.
* **Initial Setup Check:** Verify Cypress package execution and check browser availability (`npx cypress verify`).

---

## 📋 Common & Useful Workflows

```bash
# 1. Open the interactive Cypress Test Runner GUI
npx cypress open

# 2. Run all E2E test specs headlessly in CI mode
npx cypress run

# 3. Run a specific test spec file
npx cypress run --spec "cypress/e2e/login.cy.js"

# 4. Run tests against a specific browser target (e.g. chrome, firefox)
npx cypress run --browser chrome

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common Cypress execution failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **Element Not Found / Timeout** | Brittle selector or slow asynchronous DOM rendering. | Selector specificity, CSS path stability, and element visibility states. | Refactor to use dedicated data attributes (e.g., `data-testid`) instead of structural CSS classes. |
| **Test Flakiness in CI** | Environment timing variance or un-intercepted network requests. | `cy.intercept` stubs and asynchronous API response timing. | Add explicit network waiting blocks (`cy.wait()`) or stable assertion retries. |
| **Cross-Origin Policy Error** | Test navigates across multiple distinct superdomains. | Cypress domain configuration limits and navigation URLs. | Refactor test flow or use `cy.origin()` blocks for multi-domain jumps. |
| **State Leak Between Tests** | Shared application state or dirty session cookies remaining. | Test hooks (`beforeEach` / `afterEach`) and database teardowns. | Ensure proper state resetting, cache clearing, or session cleanup per spec. |
