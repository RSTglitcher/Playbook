# 📘 Kubernetes Orchestration

:::tip

## Kubernetes Orchestration

**What is it?** 
Kubernetes (K8s) is a container orchestration platform that automates deployment, scaling, and management of containerized applications. It enables microservices architectures, declarative infrastructure, and resilient distributed systems.

### 📚 Related Theory References
* Workflows & Orchestration — Core container scheduling, declarative desired-state reconciliation, and cluster resilience models.
:::

## 🧭 When to Use It

| When to Use | When Not to Use |
| :--- | :--- |
| • Microservices architectures requiring automated failover and scaling.<br>• Multi-tenant shared enterprise infrastructure with strict isolation requirements.<br>• Complex CI/CD-driven container deployments and rolling updates. | • Simple single-service applications or monolithic workloads without orchestration needs.<br>• Ephemeral batch jobs that can run on simpler serverless runtimes.<br>• Low-latency bare-metal systems where virtualization overhead cannot be tolerated. |

## 🚀 Getting Started & Prerequisites

What prerequisites, dependencies, or initial configurations are required before interacting with Kubernetes?
1. **Local Environment:** CLI client utilities installed locally (`kubectl`, `k9s`, or Helm package manager).
2. **Configuration Setup:** Validated cluster configuration file (`kubeconfig`) placed in `~/.kube/config` with correct context and credential bindings.

---

## 🔑 Tool Requirements

* **Access URL / Portal:** Kubernetes API server endpoint URL or enterprise cluster dashboard.
* **Authentication Method:** OIDC tokens, client certificates, or IAM role integration mapped via Role-Based Access Control (RBAC).
* **Initial Setup Check:** Verify cluster connectivity and node health using command-line probes (`kubectl cluster-info` and `kubectl get nodes`) before deploying resources.

## 📋 Common & Useful Workflows

```bash
# 1. Check active cluster contexts and health indicators
kubectl config get-contexts
kubectl cluster-info

# 2. Deploy workloads from declarative YAML manifests
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml

# 3. Inspect running pods, resource consumption, and logs
kubectl get pods -n production -o wide
kubectl logs -f deployment/my-service-app -n production
kubectl top nodes

# 4. Manage rollouts and execute live rollbacks if deployment fails
kubectl rollout status deployment/my-service-app
kubectl rollout undo deployment/my-service-app

```

## 🚨 Operational Triage Snapshots

:::danger
Quick-reference diagnostics for common Kubernetes platform failures:
:::

| Symptom / Telemetry | Root Cause | What to Check | Immediate Action |
| --- | --- | --- | --- |
| **Pod CrashLoopBackOff** | Container application crash on startup, missing environment variables, or config error. | Pod description logs (`kubectl describe pod`) and container stdout logs. | Fix code/configuration bugs, update container images, or restart the pod. |
| **Node Not Ready** | Underlying compute node down, network partition, or Kubelet failure. | Node event history, cloud provider host status, and Kubelet service health. | Reboot the node or investigate cloud provider infrastructure alerts. |
| **PersistentVolume Pending** | Missing storage class, unfulfilled volume capacity claims, or driver error. | PVC status events, storage class definitions, and PV binding availability. | Provision matching storage classes or fix PVC request limits. |
| **Service Unreachable** | Misconfigured selector labels, missing network policies, or broken endpoints. | Service endpoints (`kubectl get endpoints`) and network policy rules. | Correct service-to-pod selector tags or adjust cluster network routing rules. |
